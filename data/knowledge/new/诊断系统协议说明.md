# 诊断系统协议说明

# 用户规则协议说明

这份文档给外部用户使用，说明如何编写诊断规则。

系统支持两种接入方式：

- 本地规则：使用 YAML 文件，开机自动加载

- 远端规则：通过 WebSocket 动态注册、更新、注销

两种方式使用的是同一套规则结构。

- 本地 YAML：只写 `event`

- WebSocket：在外层多一个 `action`，默认为**\<机器人ip\>:8058**

- 二开内容

    - 当前版本只支持 `shell` 脚本，不支持 Python、Lua 或其他脚本类型。

---

# 协议结构

## 本地 YAML

```YAML
event:
  name: 电池低电量检测
  rule:
    field: battery_level
    op: less_than
    value: 0.2
  alarm:
    major_code: 10
    minor_code: 001
    name: 电池电量低
    severity: 3
    description: 检测到电池电量低于阈值
    recovery: 请尽快充电或更换电池
    use_tts: true
    audio_path: /opt/robot/audio/battery_low.wav
```

## WebSocket 注册

```JSON
{
  "action": "register",
  "event": {
    "name": "电池低电量检测",
    "enabled": true,
    "rule": {
      "field": "battery_level",
      "op": "less_than",
      "value": "0.2"
    },
    "alarm": {
      "major_code": "10",
      "minor_code": "001",
      "name": "电池电量低",
      "severity": 3,
      "description": "检测到电池电量低于阈值",
      "recovery": "请尽快充电或更换电池",
      "use_tts": true,
      "audio_path": "/opt/robot/audio/battery_low.wav"
    }
  }
}
```

## 用户需要知道的核心概念

用户只需要关心三件事：

- 监控哪个字段

- 满足什么规则

- 触发什么告警

例如：

- 字段：`battery_level`

- 规则：小于 `0.2`

- 告警：播报“电池电量低”

用户不需要关心底层 topic、消息类型或内部解析实现。

## 参数说明

### 顶层参数

**WebSocket 顶层**

|**参数**|**是否必填**|**类型**|**说明**|
|---|---|---|---|
|action|是|string|动作类型，支持 register（注册）、update（更新）、unregister（注销）、reload\_data\_views（重载）、describe\_data\_view\_fields（加载支持的参数）|
|event|注册/更新时必填|object|一条完整规则或更新内容|

**本地 YAML 顶层**

|**参数**|**是否必填**|**类型**|**说明**|
|---|---|---|---|
|event|是|object|一条完整规则|

### `event` 参数

|**参数**|**是否必填**|**类型**|**说明**|
|---|---|---|---|
|id|否|string|事件标识。更新或注销时推荐使用；注册成功后服务端会返回。查询方式见8 查询注册事件|
|name|否|string|规则名称，建议填写，便于展示和更新定位|
|rule|注册时必填|object|规则定义|
|enable|是|bool|是否启动该项规则|
|alarm|注册时必填|object|告警定义|

说明：

- 注册时通常传 `name + rule + alarm`

- 更新时传 `id` 或 `name` 作为定位条件，再传需要修改的内容

- 注销时推荐传 `id`

### `rule` 参数

|**参数**|**是否必填**|**类型**|**说明**|
|---|---|---|---|
|field|常用|string|字段名，例如 battery\_level，可用字段见 7 查询可用字段|
|description|可选|string|字段中文短描述，例如 电池电量。如果传了它，系统会自动找到对应字段|
|script\_path|脚本规则时必填|string|本地 shell 脚本绝对路径|
|op|是|string|运算符|
|value|某些规则必填|string/number/bool|比较目标值|
|value\_field|可选|string|与另一个字段做比较|
|value\_description|可选|string|另一个字段的中文短描述|
|conditions|复合规则必填|array\<object\>|多条件子规则列表|
|within\_seconds|timestamp\_recent 时必填|number/string|最近多少秒内|
|min|between 时必填|number/string|范围下界|
|max|between 时必填|number/string|范围上界|

补充说明：

- `field` 和 `description` 二选一即可

- 如果使用脚本规则，则传 `script_path`，不再传 `field`

- `value_field` 和 `value_description` 二选一即可

- 如果是多条件规则，使用 `op + conditions`

脚本规则说明：

- 后端会执行已注册的本地 `.sh` 文件

- 脚本最后一行输出 `true` 或 `false`

- 也支持 `1/0`、`yes/no`、`on/off`

- 若脚本执行失败或输出无法识别，会记录错误日志，并跳过当前事件本轮执行

### `alarm` 参数

|**参数**|**是否必填**|**类型**|**说明**|
|---|---|---|---|
|major\_code|是|string|告警大类编码|
|minor\_code|是|string|告警子类编码|
|name|是|string|告警名称|
|severity|是|int/string|告警等级，支持 1/2/3/4 或 info/warn/critical/emergency|
|description|否|string|告警描述|
|recovery|否|string|恢复建议或处理建议|
|use\_tts|否|bool|true 表示优先 TTS 播报|
|audio\_path|否|string|音频文件路径|

# 常见规则写法

## 单条件规则

```YAML
rule:
  field: battery_level
  op: less_than
  value: 0.2
```

含义：

- 当 `battery_level < 0.2` 时触发

## 多条件规则

```YAML
rule:
  op: and
  conditions:
    - field: lidar_online
      op: boolean_true
    - field: lidar_hz
      op: less_than
      value: 5.0
```

含义：

- 雷达在线

- 并且雷达频率低于 5

- 两个条件同时满足时触发

## 字段对字段比较

```YAML
rule:
  field: battery_voltage
  op: less_than
  value_field: battery_voltage_min
```

含义：

- 当 `battery_voltage < battery_voltage_min` 时触发

## 使用中文描述写规则

```YAML
rule:
  description: 电池电量
  op: less_than
  value: 0.2
```

含义：

- 系统会先把“电池电量”映射到对应字段

- 再按正式字段执行规则

- description 与 field 的对应关系可以通过 websocket 协议获取

## 使用 shell 脚本写规则

```YAML
rule:
  script_path: /navi_ws/src/customer_scripts/check_livox_online.sh
  op: boolean_false
```

含义：

- 先执行脚本 `/navi_ws/src/customer_scripts/check_livox_online.sh`

- 如果脚本结果为 `false`，则触发告警

# 运算符说明

## 逻辑运算

|**运算符**|**说明**|
|---|---|
|and|所有子条件都满足时命中|
|or|任意一个子条件满足时命中|

## 通用比较

|**运算符**|**说明**|
|---|---|
|equals|等于|
|not\_equals|不等于|
|exists|字段存在|
|not\_exists|字段不存在|
|empty|值为空|
|not\_empty|值非空|
|fields\_equal|当前字段与另一个字段值相等|
|equal\_fields|fields\_equal 的同义写法|

## 数值和时间比较

|**运算符**|**说明**|
|---|---|
|greater\_than|大于|
|greater\_or\_equal|大于等于|
|less\_than|小于|
|less\_or\_equal|小于等于|
|between|在指定范围内|
|timestamp\_recent|在最近若干秒内|

## 布尔比较

|**运算符**|**说明**|
|---|---|
|boolean\_true|值为真|
|boolean\_false|值为假|

## 字符串和列表比较

|**运算符**|**说明**|
|---|---|
|contains|包含指定内容|
|not\_contains|不包含指定内容|
|regex\_match|正则匹配|
|list\_contains|列表包含指定元素|
|length\_gt|长度大于指定值|

# Websocket 接口

|action|说明|
|---|---|
|`register`|新增并应用规则|
|`update`|更新并应用规则|
|`unregister`|注销规则|
|`list_events`|查询已注册规则|
|`list_alarms`|查询当前触发中的告警|
|`describe_data_view_fields`|查询可用的配置字段（例如电池电量等）|
|`reload_data_views`|重载可获取的配置字段|
|`reload_local_rules`|重载本地规则 YAML|
|`diagnose_once`|对指定告警码手动执行一次诊断|
|`get_diagnosis_state`|查询诊断状态机状态|
|`list_bash_rules`|查询默认 Bash 规则目录下的 `.sh` 文件|
|`upload_bash_rule`|上传 Bash 规则文件|

## register

新增规则，成功后写入用户规则目录并注册到运行时。

请求：

```JSON
{
  "action": "register",
  "event": {
    "name": "电池低电量检测",
    "enabled": true,
    "rule": {
      "field": "battery_level",
      "op": "less_than",
      "value": 20,
      "for_seconds": 3
    },
    "alarm": {
      "major_code": "10",
      "minor_code": "001",
      "name": "电池电量低",
      "severity": 3,
      "description": "检测到电池电量低于阈值",
      "recovery": "请尽快充电或更换电池",
      "use_tts": true,
      "audio_path": ""
    }
  }
}
```

响应：

```JSON
{
  "success": true,
  "action": "register",
  "message": "event applied, code=10-001",
  "event_id": "5c2e1d72-0012-4000-9ca6-0ff1c65ec9c6",
  "event_name": "电池低电量检测",
  "file_path": "/path/to/user_rules/battery_low.yaml"
}
```

## register Bash 规则

请求：

```JSON
{
  "action": "register",
  "event": {
    "name": "自定义 Bash 检测",
    "enabled": true,
    "rule": {
      "script_path": "check_custom.sh",
      "op": "boolean_true"
    },
    "alarm": {
      "major_code": "99",
      "minor_code": "900",
      "name": "自定义 Bash 告警",
      "severity": 3,
      "description": "脚本返回 true",
      "recovery": "请查看脚本输出",
      "use_tts": false,
      "audio_path": ""
    }
  }
}
```

响应同 `register`。后端会把规则归一化为：

```JSON
{
  "provider": {
    "tool": "script_bool",
    "script_path": "/absolute/path/config/bash_rules/check_custom.sh"
  },
  "rule": {
    "field": "result",
    "op": "boolean_true"
  }
}
```

## update

更新规则。建议传 `event.id` 定位；也可以传 `event.name` 定位。未传的字段会按已有规则合并。

请求：

```JSON
{
  "action": "update",
  "event": {
    "id": "5c2e1d72-0012-4000-9ca6-0ff1c65ec9c6",
    "enabled": false
  }
}
```

按告警码更新：

```JSON
{
  "action": "update",
  "event": {
    "alarm": {
      "major_code": "10",
      "minor_code": "001"
    },
    "enabled": true
  }
}
```

响应：

```JSON
{
  "success": true,
  "action": "update",
  "message": "event applied, code=10-001",
  "event_id": "5c2e1d72-0012-4000-9ca6-0ff1c65ec9c6",
  "event_name": "电池低电量检测",
  "file_path": "/path/to/user_rules/battery_low.yaml"
}
```

## unregister

注销规则。推荐使用 `event.id`。如果没有 ID，也可以用 `alarm.major_code + alarm.minor_code` 定位。

请求：

```JSON
{
  "action": "unregister",
  "event": {
    "id": "5c2e1d72-0012-4000-9ca6-0ff1c65ec9c6"
  }
}
```

或：

```JSON
{
  "action": "unregister",
  "event": {
    "alarm": {
      "major_code": "10",
      "minor_code": "001"
    }
  }
}
```

响应：

```JSON
{
  "success": true,
  "action": "unregister",
  "message": "event removed, code=10-001",
  "event_id": "5c2e1d72-0012-4000-9ca6-0ff1c65ec9c6",
  "event_name": "电池低电量检测"
}
```

## alarm\_add

注册一个外部触发型规则。内部会构造：

请求：

```Plain Text
string alarm_name
string major_code
string minor_code
int32 severity
string description
string recovery
bool use_tts
string audio_path
```

响应：

```Plain Text
bool success
string message
```

调用示例：

```Shell
rosservice call /zj_humanoid/disgnosis/alarm_add "alarm_name: '外部急停'
major_code: '99'
minor_code: '901'
severity: 4
description: '外部系统触发急停'
recovery: '请检查外部控制系统'
use_tts: true
audio_path: ''"
```

响应示例：

```YAML
success: true
message: "event applied, code=99-901"
```

```Plain Text
int32 severity
```

`severity=0` 表示全部。
