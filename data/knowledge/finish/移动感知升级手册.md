# 文档说明

本文档用于指导客户完成以下三种升级操作，并说明每种方式适用的场景：

1. 使用 `.run` 升级包进行单独模块升级
2. 使用项目升级控制台进行整包升级
3. 使用项目升级控制台进行单独模块包替换

# 升级方式使用场景

| **方式**        | **说明**                                                     | **适用场景**                                                 |
| --------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| .run 单模块升级 | 用户拿到一个可执行的 .run 升级包，通过命令行在机器人上执行升级 | 现场只需要升级 1 个或少量模块；交付的是独立升级包；网络环境简单，适合远程指导客户操作 |
| 项目整包升级    | 通过升级控制台上传整机安装包或填写文件服务器路径，执行整项目升级 | 版本整体切换；需要一次性升级整套软件；希望按项目标准流程完成部署 |
| 项目模块包替换  | 通过升级控制台上传某个模块的 deb 包，替换项目中的单独模块并重启该模块 | 只修复某个模块；不希望影响其他模块；需要快速热替换单模块包   |

建议按下面原则选择：

- 需要整机整体切版本时，使用“项目整包升级”
- 只改一个模块，且现场已有升级控制台时，优先使用“项目模块包替换”
- 只向客户单独交付一个 `.run` 包，或现场只能按命令行方式操作时，使用 “`.run` 单模块升级”

# 方式一：使用 `.run` 升级

## 准备升级包

用户会收到一个`.run`包

以下步骤以 `navigation_upgrade_wa_v1.4.0.run` 为例。

run包地址：http://10.51.33.211:10000/#/modules/tool/nav_upgrade/release（仅内网用户使用，按版本取）

## 使用 `scp` 拷贝到机器人

先将升级包拷贝到机器人 `/tmp` 目录：

```Bash
scp ./navigation_upgrade_wa_v1.4.0.run <user>@<robot_ip>:/tmp/
```

例如：

```Bash
scp ./navigation_upgrade_wa_v1.4.0.run naviai@192.168.1.100:/tmp/
```

## `ssh` 登录机器人

```Bash
ssh <user>@<robot_ip>
```

例如：

```Bash
ssh naviai@192.168.1.100
```

## 进入 `/tmp` 并赋予执行权限

```Bash
cd /tmp
chmod +x navigation_upgrade_wa_v1.4.0.run
```

如果文件名不同，请替换为实际收到的 `.run` 文件名。

## 查看帮助

执行安装前，建议先查看升级包支持的命令：

```Bash
./navigation_upgrade_wa_v1.4.0.run --help
```

## 常用安装命令

单模块安装：

```Bash
./navigation_upgrade_wa_v1.4.0.run --chassis
./navigation_upgrade_wa_v1.4.0.run --map_server
./navigation_upgrade_wa_v1.4.0.run --navigation
./navigation_upgrade_wa_v1.4.0.run --nviz
./navigation_upgrade_wa_v1.4.0.run --perception
./navigation_upgrade_wa_v1.4.0.run --sensor_lidar
```

保留现场已有 `config`、不覆盖配置文件：

```Bash
./navigation_upgrade_wa_v1.4.0.run --navigation --keep-config
./navigation_upgrade_wa_v1.4.0.run --perception --keep-config
```

如确实需要使用 `.run` 做整包安装，也支持：

```Bash
./navigation_upgrade_wa_v1.4.0.run --all
./navigation_upgrade_wa_v1.4.0.run --all --keep-config
```

## docker 重启说明

安装完成后，脚本会自动执行类似命令：

```Bash
docker compose down <module>docker compose up -d <module>
```

如果目标机器较老，不支持 `docker compose`，脚本会自动切换为：

```Bash
docker-compose down <module>docker-compose up -d <module>
```

## 完整示例

示例：升级 `wa` 包中的 `navigation`，并保留现场配置

```Bash
scp ./navigation_upgrade_wa_v1.4.0.run naviai@192.168.1.100:/tmp/
ssh naviai@192.168.1.100
cd /tmp
chmod +x navigation_upgrade_wa_v1.4.0.run
./navigation_upgrade_wa_v1.4.0.run --navigation --keep-config
```

# 方式二：整包升级

## 方式说明

该方式通过项目中的升级控制台执行整项目升级，适合整机版本切换或一键升级整套软件。

项目当前保留的正式部署路径有两条：

- `整包部署`
- `模块部署`

其中本节对应的是 `整包部署`。

## 适用场景

- 需要一次性升级整套项目，而不是只换单个模块
- 需要按项目标准部署流程执行升级
- 安装包已经准备为整机升级包，或已放在文件服务器上

## 操作步骤

1. 启动升级控制台服务
2. 浏览器访问 `http://<机器人ip>:8000`（若访问不了，先按照第7章部署升级控制网页）
3. 进入首页的 `部署/整包部署` 区域
4. 选择部署目标
5. 上传整包安装文件，或者填写文件服务器路径
6. 提交任务，等待系统执行安装
7. 如页面进入等待确认状态，根据提示确认机型
8. 在 `后台任务` 页面查看执行进度和日志

## 整包部署的目标说明

- `ORIN`：默认在当前部署机本地执行
- `PICO`：通过页面中保存的 SSH 信息直连目标设备执行

## 注意事项

- 如果进入“等待确认”，说明安装包机型识别已完成，但仍需要人工确认机型
- 使用文件服务器路径时，前提是后端机器可以访问该文件服务器（仅内网用户可以使用）
- `PICO` 路线依赖页面中预先保存的 SSH 主机、端口、用户名和密码

# 方式三：单独模块包替换

## 方式说明

该方式通过升级控制台中的 `模块部署` 页面，将单独模块的 `deb` 包替换到项目目录中，并自动重启对应模块。

这是项目内“替换单模块包”的推荐方式，适合小范围修复和快速更新。

## 适用场景

- 只需要修复或升级某一个模块
- 不希望重新安装整套项目
- 需要快速替换模块包并自动重启对应服务

## 当前支持的模块

- `chassis`
- `perception`
- `sensor_lidar`
- `navigation`
- `map_server`
- `nviz`

## 操作步骤

1. 启动升级控制台服务
2. 浏览器访问 `http://<机器人ip>:8000`（若访问不了，先按照第7章部署升级控制网页）
3. 进入首页的 `部署模块部署` 区域
4. 在下拉框中选择要替换的模块
5. 上传该模块对应的 `deb` 包，或者填写文件服务器路径（仅内网用户可以使用）
6. 提交任务

# 三种方式的选择建议

可以按下面的原则判断：

- 客户手里只有一个 `.run` 文件，并且希望通过命令行直接升级时，使用“`.run` 单模块升级”
- 需要把整套项目一次性升级到某个版本时，使用“项目整包升级”
- 只想替换 `navigation`、`perception`、`sensor_lidar` 等某一个模块时，使用“项目模块包替换”

如果不确定该使用哪种方式，优先按“影响范围”判断：

- 影响整个项目：选“整包升级”
- 只影响一个模块：选“模块包替换”或 “`.run` 单模块升级”
- 现场只接受客户侧命令行执行：选 “`.run` 单模块升级”

# 升级控制台安装方式

## 准备安装包

发送给客户的安装包例如：

- `zj-humanoid-robot-web_1.0.0-0jammy_arm64.deb`

以下步骤以 `zj-humanoid-robot-web_1.0.0-0jammy_arm64.deb` 为例。

deb包地址：http://10.51.33.211:10000/#/modules/tool/robot-web/release（仅内网用户使用，取最新）

## 完整示例

```Bash
scp ./zj-humanoid-robot-web_1.0.0-0jammy_arm64.deb naviai@192.168.1.100:/tmp/
ssh naviai@192.168.1.100
cd /tmp
sudo dpkg -i zj-humanoid-robot-web_1.0.0-0jammy_arm64.deb
sudo systemctl status robot-web.service
```
